# OCS 처방 도우미

흐름 프로그램에 지정된 **오늘 검사**를 OCS 오더 입력창에 대신 넣어 주는 작은 프로그램입니다. 의사 PC(윈도우 11)에서 AutoHotkey v2로 실행합니다.

- **F9** — OCS에 열려 있는 환자의 검사 처방을 넣습니다.
- **F10** — 명단 모드입니다. 오늘 처방을 넣을 환자를 예약 순서대로 **OCS 외래 명단에서 찾아 더블클릭**해 열고 넣은 뒤, **환자마다 멈춥니다**. 오더를 확인하고 서명한 뒤 F9를 누르면 다음 환자로 넘어갑니다.
- 다 넣으면 흐름 프로그램 검사실 화면의 **[처방 전]이 '처방 완료'로** 바뀝니다(버튼을 직접 누른 것과 같은 기록).
- **서명(F2)은 절대 하지 않습니다.** OCS에서 D/C인 **Delete 키도 쓰지 않습니다.**

**화면 위치를 외우지 않고, 매번 OCS 화면에서 찾습니다.** 창을 옮기거나 칸 크기·배치가 바뀌어도, 화면에 보이기만 하면 따라갑니다. 찾지 못하면 아무것도 누르지 않고 멈춥니다.

빨리 찾는 순서 (앞에서 찾으면 뒤는 하지 않음):

1. **그림 찾기** (0.1초 안쪽): 사람이 아이콘 모양을 보고 바로 찾듯이, 등록할 때 찍어 둔 작은 그림(Patient List 아이콘, 처방 입력창의 '입력창' 글자, 명단의 '환자번호' 머리글)을 화면에서 찾습니다.
2. **좁은 곳만 글자 인식**: 환자번호는 지난번에 번호가 보이던 좁은 띠, 기준 글자는 등록한 자리 근처, 외래 명단은 '환자번호' 세로줄만 읽습니다(윈도우에 들어 있는 글자 인식 기능).
3. **창 전체 글자 인식** (몇 초): 위에서 못 찾을 때만. 이때 찾은 자리·모양을 기억해 두어 다음부터는 1·2로 찾습니다.

기다리는 시간도 줄였습니다. 검색어를 친 뒤·처방을 고른 뒤 **정해진 시간을 다 기다리지 않고, 후보 목록이 뜨거나 닫혀 화면이 멈추면 바로** 다음으로 갑니다(설정 파일의 기다리는 시간은 '최대'로 씀). 처방 입력창은 확인 창을 띄우기 전에 미리 찾아 두어서 [예]를 누르면 바로 넣기 시작합니다.

> 병원 전산 프로그램을 자동으로 조작하는 도구입니다. 전산팀(의료정보팀)의 승인을 받은 뒤 쓰시고, 처음에는 한 PC에서 검사 한두 개로 시작하세요.

## 1. 준비 (한 번만)

### 1-1. 흐름 프로그램에 OCS 입력법 등록

흐름 프로그램 → **설정 → 검사실 · 검사** → 검사의 **[자세히]** → 아래쪽 **OCS 처방 입력법**.

| 칸 | 적는 것 |
|---|---|
| 양측 | 양안 검사일 때 OCS 입력창에 칠 검색어와 후보 목록에서 ↓를 누를 횟수 |
| 편측 | 한쪽 눈(우안·좌안) 검사일 때의 검색어와 ↓ 횟수 |

- 예: VF 양측 = `Visual field test`, ↓ 1번 / VF 편측 = `Visual field test`, ↓ 0번
- ↓ 0번은 검색어를 친 뒤 바로 Enter를 누른다는 뜻입니다.
- **OCT**처럼 세부 종류의 눈 위치 그룹이 'M,D OCT'와 'OCTA'로 나뉜 검사는 **OCT 양측·편측, OCTA 양측·편측** 네 칸이 나옵니다. Macular와 Disc를 같이 해도 OCT 처방은 하나만 넣습니다.
- 비워 둔 칸은 도우미가 넣지 않고 **'직접 입력'** 으로 알려 줍니다. 한 검사의 처방(예: OCT와 OCTA) 중 하나라도 비어 있으면 그 검사는 통째로 직접 입력입니다.
- OCS에 처방하지 않는 검사는 검사 줄의 **[처방 없음]** 칩을 켜 두세요. 도우미도 건너뜁니다.

같은 검색어를 치면 후보 순서가 항상 같다는 전제로 동작합니다. 새 검사를 등록하면 OCS에서 한 번 직접 확인하세요.

### 1-2. 도우미 설치 (의사 PC)

1. https://www.autohotkey.com 에서 **v2.0**을 받아 설치합니다(v1.1이 아닌 **v2**).
2. 업데이트 zip 안의 `ocs-helper` 폴더를 **통째로**(안의 `Lib` 폴더 포함) 의사 PC에 복사합니다(예: `문서\OCS도우미`).
3. `ophflow-helper.ahk`를 더블클릭하면 작업 표시줄 오른쪽 아래에 초록색 **H** 아이콘이 생깁니다.
   - 설정 파일 `ophflow-helper.ini`, 기록 파일 `ophflow-helper.log`, 찍어 둔 그림을 넣는 `img` 폴더가 같은 폴더에 생깁니다.
   - PC를 켤 때마다 자동으로 실행하려면 `Win + R` → `shell:startup` 폴더에 `ophflow-helper.ahk`의 바로가기를 넣으세요.

### 1-3. 등록 (설정 창)

트레이 아이콘(H)을 더블클릭하면 설정 창이 열립니다. 항목을 고르고 **[선택 항목 등록]**.

| 항목 | 하는 방법 |
|---|---|
| 흐름 프로그램 서버 주소 | 브라우저 주소창에 쓰는 주소를 그대로 적습니다(예: `http://192.168.0.10:3000`, 이 PC가 서버 PC면 `http://localhost:3000`). 적으면 바로 연결을 시험합니다 |
| OCS 창 | OCS 진료 화면 위에 마우스를 올리고 **F8** |
| 처방 입력창 | 오더발행의 처방 입력창 안 **'입력창' 글자 위**에 마우스를 올리고 F8 (입력창이 비어 있을 때) |
| 외래 명단 여는 버튼 | (명단 모드, 꼭 필요) **외래 명단이 닫힌 화면에서** 왼쪽 메뉴의 **Patient List** 아이콘 한가운데에 마우스를 올리고 F8. 다음 환자로 넘어갈 때 이 버튼을 눌러 명단을 엽니다 |

- F8을 누를 때 클릭은 하지 않아도 됩니다. 취소는 Esc.
- F8을 누르면 **마우스가 잠깐 위(또는 아래)로 비켜났다가 돌아옵니다.** 버튼이 마우스에 반응해 색이 바뀐 모양이 찍히지 않도록 하는 것이니 놀라지 마세요.
- **처방 입력창·명단 버튼은 위치가 아니라 '모양(작은 그림)'과 '기준 글자'를 기억합니다.** F8을 누르면 모양을 `img` 폴더에 찍어 두고, 마우스 근처 글자(예: `입력창`, `Patient`)를 빨간 네모로 보여 줍니다. 앞으로는 모양을 먼저 찾고, 못 찾으면 글자를 찾아서 같은 자리를 누릅니다. 명단 버튼은 글자도 못 읽으면 **창 왼쪽 위 기준 위치**로 누릅니다(창을 옮겨도 따라감).
- 같은 모양·글자가 화면에 여러 개면(예: 입력창이 위아래 두 개) 등록할 때 자리와 가장 가까운 것을 고릅니다. 비슷한 모양이 너무 많거나 거의 한 가지 색이면 그림은 기억하지 않고 글자·위치로만 찾습니다(등록 결과 창에 나옴).
- 예전 버전에서 등록했다면 **두 항목을 한 번씩 다시 등록**하세요(모양을 찍어 두려고). 처방 입력창은 다시 등록하지 않아도 글자로 한 번 찾을 때 모양을 스스로 기억합니다.
- 환자번호는 등록할 필요가 없습니다. 화면에 여러 번 보이는 번호(오더발행·EMR 제목의 `[16318174]` 등)를 읽습니다.

### 1-4. 화면 글자 읽기 시험

등록한 뒤 OCS에서 환자 화면을 열어 두고 **[화면 글자 읽기 시험]**(트레이 메뉴에도 있음)을 누르세요. 아무것도 누르지 않고 읽기만 하며, 찾은 곳을 6초 동안 네모로 보여 줍니다.

결과 창은 두 부분입니다.

- **실제로 쓰는 빠른 방법**: 좁은 띠에서 읽은 환자번호와 걸린 시간, 그림 찾기 3가지(처방 입력창 · Patient List 버튼 · 외래 명단 머리글)를 찾았는지와 걸린 시간.
- **화면 전체 글자 읽기** (확인용): 그림으로 못 찾을 때 쓰는 느린 방법이 제대로 되는지.

| 색 | 뜻 |
|---|---|
| 초록 | 읽은 환자번호 |
| 빨강 | 처방 입력창 · 명단 버튼을 누를 자리 (그림으로 찾았으면 그림 크기의 네모) |
| 파랑 | (외래 명단이 열려 있을 때) 명단 머리글 · 명단에서 읽은 환자번호 |

- 이 시험을 하면 그 자리에서 **환자번호 띠, 처방 입력창 모양, (명단이 열려 있으면) 명단 머리글 모양을 기억**해 둡니다. 환자 화면에서 한 번, 외래 명단을 연 화면에서 한 번 해 두면 처음부터 빠릅니다.
- 환자번호를 못 읽거나 엉뚱한 번호가 나오면 설정 파일의 `OcrScale`을 3으로 올려 보세요.

### 1-5. 화면 요소 확인 (UIA 시험) — 더 빠르게 할 수 있는지 알아보기

OCS가 화면의 글자·칸을 **윈도우 접근성 기능(UI Automation)** 으로 알려 준다면, 글자 인식·그림 찾기 없이 **곧바로** 환자번호를 읽고 입력창·버튼을 찾을 수 있습니다(지금보다 훨씬 빠르고 정확). OCS가 이것을 지원하는지 알아보는 도구입니다.

1. 트레이 아이콘 우클릭 → **화면 요소 확인 (UIA 시험)** → 작은 창이 뜹니다(`uia-check.ahk`).
2. OCS에서 ① 환자번호 ② 처방 입력창 ③ Patient List 버튼 ④ 외래 명단의 환자 줄 위에 차례로 마우스를 올리고 **F7**.
   처음 F7을 누를 때 그 창 전체도 한 번 세어 봅니다(몇 초, 진료가 한가할 때 하세요).
3. **[복사]** → Claude에게 붙여 넣어 주세요. 결과를 보고 도우미를 더 빠른 방식으로 바꿀 수 있는지 알려 드립니다.

- 읽기만 합니다(누르거나 입력하지 않음). 파일로 저장하지 않습니다.
- 이름·번호는 **가려서**(한글 → ○, 숫자 → #) 보여 줍니다. 복사하기 전에 내용을 한 번 훑어보세요.

## 2. 연습 모드로 먼저 확인하기

OCS를 건드리지 않고 서버와 주고받는 것까지 확인할 수 있습니다.

1. 트레이 아이콘 우클릭 → **연습 모드 (메모장)**
2. 메모장을 열고 그 안에서 **F9**
3. 환자번호를 물으면 오늘 흐름 명단에 있는 번호를 넣습니다.
4. 메모장에 `[처방 1] 입력창 클릭 → 'Visual field test' 입력 → ↓ 1번 → Enter` 같은 줄이 적힙니다. 실제 OCS에서는 이 순서대로 누릅니다.
5. 마지막에 흐름 프로그램에도 처방 완료로 표시할지 묻습니다. **가상 환자로 연습할 때만 '예'** 를 누르세요.

메모장에서 **F10**을 누르면 명단 모드도 연습할 수 있습니다. OCS 화면을 제대로 읽는지는 1-4의 시험으로 확인하세요.

## 3. 사용법

### F9 — 지금 열린 환자

1. OCS에서 환자를 열고 오더발행 화면이 보이게 둡니다(입력창은 비워 두기).
2. **F9**
3. 도우미가 화면에서 환자번호를 읽고 → 서버에서 오늘 검사를 받아 → 확인 창을 띄웁니다.
   > 윤지아 (6100259) — VF 양측, OCT 양측 … 넣을까요?
4. **[예]** 를 누르면 화면을 다시 읽어 환자가 그대로인지 확인하고, 처방 입력창을 찾아 한 줄씩 넣습니다. **넣는 동안 마우스·키보드를 만지지 마세요. 멈추려면 Esc.**
5. 오더 목록을 확인하고 **직접 서명**합니다.

진료 중에 검사를 추가하면 그 검사는 [처방 전]으로 돌아갑니다. F9를 다시 누르면 새로 생긴 것만 넣습니다.

### F10 — 명단 모드 (외래 명단에서 찾아서)

1. OCS 메인 화면에서 **F10** → 교수와 '접수한 환자만'을 고르고 [시작] → 오른쪽 위에 명단 창이 뜹니다(환자를 찾고 넣는 동안에는 OCS 화면을 가리지 않도록 잠깐 숨었다가 다시 나타납니다).
2. **F9** → 첫 환자의 확인 창 → [예] →
   - 외래 명단이 닫혀 있으면(다음 환자로 넘어갈 때는 보통 진료 화면) **Patient List 버튼을 눌러 명단을 열고**, 명단이 뜰 때까지 확인합니다.
   - 명단이 열렸는지는 '환자번호' 머리글로 알아봅니다. 한 번 글자로 찾으면 머리글 모양을 기억해 두어 다음부터는 그림으로 바로 찾습니다. 머리글을 못 읽으면 환자번호가 세로로 3개 이상 늘어서 있는지로 알아봅니다.
   - 명단의 **'환자번호' 칸에서 그 번호를 찾아 더블클릭**합니다(검색칸은 쓰지 않음). 화면에 없으면 마우스 휠을 조금씩 굴려 아래로 끝까지, 없으면 위로 끝까지 찾습니다. 한 번에 너무 많이 굴려 건너뛴 줄이 생기면 되돌아가서 더 조금씩 굴립니다.
   - 환자 화면이 열리면 환자번호가 같은지 확인한 뒤 처방을 넣고 **멈춥니다**.
3. 오더를 확인하고 **서명**한 뒤 **F9** → 다음 환자.
4. 환자를 못 찾거나 멈추면 명단 창에 이유가 나옵니다. F9로 다시 하거나 **[이 환자 건너뛰기]**.
5. 다 끝나면 **[명단 모드 끝내기]**(또는 F10).

명단 창의 [다음 환자] 버튼을 눌러도 F9와 같습니다. 확인 창이 번거로우면 설정 파일에서 `BatchConfirm=0`으로 바꿀 수 있습니다(그러면 F9를 누르는 것이 확인이 됩니다).

## 4. 안전장치

- 서명(F2)과 Delete(D/C)는 누르지 않습니다. 입력창을 지우는 키(Ctrl+A, Delete)도 쓰지 않습니다.
- 넣기 전에 화면의 환자번호를 **두 번** 읽어서 흐름 프로그램 환자와 같은지 확인합니다(확인 창 전, 입력 직전). 명단 모드에서는 환자 화면을 연 뒤 다시 확인합니다.
- 환자번호는 화면에 **두 번 이상** 보이는 번호만 인정합니다. 애매하면 읽지 못한 것으로 보고 멈춥니다.
- 처방 입력창·명단 버튼의 모양·기준 글자를 찾지 못하면 누르지 않고 멈춥니다. 모양은 창 전체에서 1~3곳에만 보일 때만 기억합니다(흔한 모양은 쓰지 않음).
- 화면 변화를 보고 기다리는 시간을 줄이더라도, **꼭 기다리는 최소 시간**(`WaitMinAfterType`, `WaitMinAfterEnter`)은 지킵니다. 화면이 끝내 바뀌지 않으면 예전처럼 정해진 시간을 다 기다립니다.
- OCS의 작은 창(팝업)이 앞에 있으면 시작하지 않습니다. 한 줄 넣을 때마다 OCS 창이 앞에 있는지 확인하고, 팝업이 뜨거나 다른 창이 앞에 오면 즉시 멈춥니다.
- 입력창을 누른 뒤 글자 커서가 입력창 근처에 없으면 멈춥니다(OCS가 커서 위치를 알려주는 경우만).
- 언제든 **Esc**로 멈출 수 있습니다. 멈추면 몇 건을 넣었는지 알려 주고, **처방 줄을 모두 넣은 검사만** 처방 완료로 표시합니다.
  - OCT와 OCTA처럼 한 검사에 처방이 둘인데 하나만 넣고 멈췄다면, 도우미가 기억해 두었다가 같은 환자에서 다시 F9를 누를 때 **남은 것만** 넣습니다(도우미를 끄면 이 기억은 지워지니, 그 전에 마무리하세요).
  - 처방을 넣었는데 서버 문제로 처방 완료 표시만 못 했다면, 다시 F9를 눌러도 처방은 다시 넣지 않고 표시만 합니다.
- 작업 기록은 `ophflow-helper.log`에 남습니다(환자번호와 처방 이름, 걸린 시간만, 이름은 남기지 않음). 화면 글자를 파일로 저장하지는 않습니다.

## 5. 병원에서 처음 시험할 때 확인할 것

연습 모드와 화면 글자 읽기 시험이 잘 되면, OCS에서 **검사 하나만 등록한 상태로** 한 환자에 시험하세요. 아래가 맞지 않으면 설정 파일(`트레이 아이콘 → 설정 파일 열기`)을 고치고 **설정 다시 불러오기**를 누르세요.

| 확인할 것 | 맞지 않을 때 |
|---|---|
| 화면 글자 읽기 시험에서 환자번호(초록)가 맞게 잡히나요? | `OcrScale=3`. 그래도 안 되면 알려 주세요 |
| 처방 입력창(빨강)이 맞는 입력창을 가리키나요? | '입력창' 글자 위에서 다시 등록 |
| 명단을 연 상태에서 환자번호(파랑)가 잡히나요? | `OcrScale=3` |
| 명단에서 마우스 휠로 내려가나요? 한 번에 너무 많이/적게 내려가나요? | `ListScroll`(한 번에 내리는 칸 수)을 조정 |
| 검색어를 치면 후보 목록이 바로 뜨나요? | Enter를 쳐야 뜬다면 `EnterToSearch=1` |
| 후보 목록이 다 뜨기 전에 ↓가 눌리나요? (엉뚱한 처방이 들어감) | `WaitMinAfterType`을 늘립니다(예: 800). 그래도 그러면 `AdaptiveWait=0`(늘 정해진 시간을 다 기다림)으로 바꾸고 `WaitAfterType`을 늘립니다 |
| 처방을 고른 뒤 다음 줄이 너무 빨리 시작되나요? | `WaitMinAfterEnter`를 늘립니다(예: 1000) |
| 처방 한 줄씩 넣는 게 느린가요? | 기록 파일에 '입력 N건 N초'가 남습니다. OCS가 잘 따라오면 `WaitMinAfterType`(500)·`WaitMinAfterEnter`(600)·`DownDelay`(150)를 조금씩 줄여 보세요. 너무 줄이면 후보가 뜨기 전에 골라 다른 처방이 들어갈 수 있으니, 줄인 뒤 꼭 오더 목록을 확인하세요 |
| 그림으로 엉뚱한 곳을 가리키나요? (시험의 빨강·파랑 네모) | 그 항목을 다시 등록. 계속되면 `ImageFind=0`(그림 찾기 끄기, 글자로만) |
| 처방을 고른 뒤 입력창이 비워지나요? | 비워지지 않으면 알려 주세요(지우는 키를 일부러 쓰지 않습니다) |
| 처방을 고르면 작은 창(수량·부위 등)이 뜨나요? | 도우미가 멈춥니다. 알려 주시면 그 창 처리 순서를 추가하겠습니다 |
| 검색어의 영문이 한글로 바뀌어 입력되나요? | `TypeMode=paste` 또는 `text` |
| '커서가 입력창에 들어가지 않은 것 같아요'가 계속 뜨나요? | 다시 등록해 보고, 그래도 뜨면 `CaretCheck=0` |
| F9·F10이 OCS의 다른 기능과 겹치나요? | `HotkeyRun`, `HotkeyBatch`를 바꿉니다(예: `^F9` = Ctrl+F9) |

## 6. 설정 파일 (`ophflow-helper.ini`)

| 이름 | 기본값 | 뜻 |
|---|---|---|
| HotkeyRun | F9 | 현재 환자 / 명단 모드의 다음 환자 |
| HotkeyBatch | F10 | 명단 모드 시작·끝 |
| TypeMode | keys | 검색어 입력 방식: keys, text, paste |
| WaitAfterClick | 300 | 입력창을 누른 뒤 기다림(밀리초) |
| WaitAfterType | 800 | 검색어를 친 뒤 후보 목록을 기다리는 **최대** 시간 |
| EnterToSearch | 0 | 1이면 검색어 뒤에 Enter를 먼저 누름 |
| WaitAfterSearch | 800 | 위 Enter 뒤 기다리는 최대 시간 |
| DownDelay | 150 | ↓ 사이 간격 |
| WaitAfterEnter | 1200 | 처방을 고른 뒤 다음 처방까지 기다리는 **최대** 시간 |
| AdaptiveWait | 1 | 1 = 화면이 바뀐 뒤 멈추면 바로 다음으로(위 시간은 최대), 0 = 늘 위 시간을 다 기다림(예전 방식) |
| StableMs | 300 | 화면이 이만큼 그대로면 '멈췄다'고 봄 |
| WaitMinAfterType | 500 | 검색어를 친 뒤 꼭 기다리는 최소 시간 |
| WaitMinAfterEnter | 600 | 처방을 고른 뒤 꼭 기다리는 최소 시간 |
| ImageFind | 1 | 1 = 찍어 둔 그림으로 먼저 찾음(빠름), 0 = 글자 인식만 |
| ImageVariation | 30 | 그림 찾기에서 허용하는 색 차이(0~255). 모양을 자주 못 찾으면 50 |
| BatchConfirm | 1 | 명단 모드에서 환자마다 확인 창 |
| CaretCheck | 1 | 입력창 커서 확인 |
| OcrScale | 2 | 글자 인식 확대 배율 (작은 글씨는 2~3) |
| OcrLang | (비움) | 글자 인식 언어. 비우면 윈도우 기본 언어(예: `ko`, `en-US`) |
| PatientIdMin · PatientIdMax | 6 · 10 | 환자번호 자릿수 |
| ListOpenWait | 1500 | 명단 여는 버튼을 누른 뒤 기다림 |
| ListScroll | 5 | 명단에서 휠을 한 번에 굴리는 칸 수 (줄을 건너뛰면 자동으로 줄임) |
| ListMaxPages | 40 | 명단을 최대 몇 번까지 내려 볼지 |
| ChartOpenWait | 2500 | 명단에서 더블클릭한 뒤 환자 화면을 기다리는 최대 시간 (+3초). 화면이 열리는 대로 바로 넘어감 |
| [Server] Url | (없음) | 흐름 프로그램 서버 주소 |
| [Anchors] | (설정 창에서 등록) | 처방 입력창·명단 버튼의 기준 글자 |
| [Images] | (자동) | `img` 폴더 그림의 크기·누를 곳·자리. 지우면 글자로 찾으며 다시 기억함 |
| [Learned] | (자동) | 스스로 기억한 자리: 환자번호가 보이는 띠(IdBand), 외래 명단 '환자번호' 칸(ListCol). 지워도 다시 배움 |

## 7. 문제 해결

| 메시지 | 할 일 |
|---|---|
| 흐름 프로그램 서버에 연결하지 못했어요 | 서버 PC가 켜져 있는지, 설정 창의 서버 주소가 브라우저 주소와 같은지 확인 |
| 서버가 도우미 요청을 모르는 것 같아요 | 서버를 이 기능이 들어간 버전으로 업데이트하고 서버를 껐다 켜기 |
| 오늘 흐름 프로그램 명단에 없는 환자예요 | 흐름 프로그램 오늘 명단에 그 환자가 있는지, 환자번호가 같은지 확인 |
| 화면에서 환자번호를 읽지 못했어요 | 환자 화면(오더발행)이 열려 있는지 확인 → 화면 글자 읽기 시험 → `OcrScale=3` |
| 처방 입력창을 화면에서 찾지 못했어요 | 입력창이 비어 있는지, 오더발행이 가려지지 않았는지 확인. 계속되면 다시 등록 |
| 외래 명단에서 환자를 찾지 못했어요 | 명단의 날짜·진료의 조건이 맞는지, 그 환자가 명단에 있는지 확인 |
| 화면 글자를 읽지 못했어요 (언어) | 설정 파일에서 `OcrLang=en-US` (숫자와 영문은 읽음) |
| OCS의 작은 창(팝업)이 앞에 있어요 | 떠 있는 창을 닫고 OCS 메인 화면을 클릭한 뒤 다시 |
| 단축키가 안 먹어요 | OCS 창이 앞에 있어야 동작합니다. 'OCS 창'을 등록했는지 확인 |

## 8. 참고

### 서버와 주고받는 방식

도우미는 흐름 프로그램 서버의 아래 주소를 씁니다(서버 쪽 코드: `scripts/ocs-api.js`, 규칙: `src/core/ocs.js`). 답은 탭으로 나눈 글이고 첫 줄이 `OPHFLOW1 <종류>`입니다.

| 주소 | 하는 일 |
|---|---|
| `GET /api/ocs/ping` | 연결 확인 (오늘 날짜, 명단 인원, 처방 넣을 환자 수) |
| `GET /api/ocs/list` | 오늘 처방을 넣을 환자 (예약 순) |
| `GET /api/ocs/patient?id=환자번호` | 그 환자에게 넣을 처방 |
| `POST /api/ocs/done` (본문 `id=…` `tests=vf,oct`) | 넣은 검사를 처방 완료로 표시 |

메인 화면에서 날짜를 직접 정했으면 그 날짜를 오늘로 씁니다.

### 라이브러리

- `Lib\OCR.ahk`: 윈도우에 들어 있는 글자 인식(Windows.Media.Ocr)을 AutoHotkey에서 쓰게 해 주는 공개 라이브러리입니다([Descolada/OCR](https://github.com/Descolada/OCR), MIT). 저작권 문구는 `Lib\OCR-LICENSE.txt`.
- `Lib\UIA.ahk`: 윈도우 접근성 기능(UI Automation) 라이브러리입니다([Descolada/UIA-v2](https://github.com/Descolada/UIA-v2), MIT). 지금은 '화면 요소 확인'(`uia-check.ahk`)에서만 씁니다. 저작권 문구는 `Lib\UIA-LICENSE.txt`.

둘 다 고치지 않고 그대로 넣었습니다. 화면을 읽는 일은 이 PC 안에서만 하며, 화면 내용을 밖으로 보내지 않습니다. 그림 찾기는 AutoHotkey에 들어 있는 기능(ImageSearch)을 쓰고, `img` 폴더의 그림은 버튼·글자 모양만 작게 찍은 것입니다(환자 정보는 찍지 않음).
